## Problem Statement
The demo at https://jonyfs.github.io/llm-wiki-template/#graph shows a wiki as a 3D neuron brain: Canvas 2D with its own perspective, force layout, one neuron shape per page type, and three wiki operations (ingest, ask, lint) playing out on simulated data. The user wants the same view as a native Obsidian view, running on a real vault, and published in the Obsidian community directory.

## What Makes This Cool
Your real wiki lights up like a brain. Add a source and the cells fire. Ask a question and you see which pages answered it. Run lint and orphans and broken links flash. The demo only simulates this; the plugin does it for real.

## Constraints
- Plugin id and display name cannot contain "obsidian" (manifest docs). Chosen: id `llm-wiki-brain`, name "LLM Wiki Brain". Free in the registry and on GitHub (checked 2026-10-27). `brain` and `synapse` are taken.
- No Node or Electron APIs, so it works on mobile. No dependencies: reuse the demo's Canvas 2D engine.
- No `innerHTML`; use `this.app`, not the global `app` (plugin guidelines).
- About 8 brain-shaped graph plugins already exist (Brain Atlas 21 stars; the rest 0-4). Shape alone will not differentiate.

## Premises
1. Repo, plugin id and name are all `llm-wiki-brain` (user changed this from `obsidian-brain`).
2. Port the demo engine into an `ItemView`. Read links from `metadataCache.resolvedLinks`. Node types come from `wiki/{sources,entities,concepts,syntheses}`, with a folder/tag fallback.
3. The differentiator is live wiki behavior on real events, not the shape.
4. Distribution: GitHub release, BRAT beta, then submission at community.obsidian.md (not a PR to obsidian-releases).
5. Build and verify in a real vault first; create the public repo only on the user's go.

## Approaches Considered
- A. Minimal port: demo engine on real links, no live ops. Rejected: same purpose as 8 existing plugins.
- B. Port plus live wiki operations. CHOSEN.
- C. Agent-activity brain (B plus real-time view of AI edits via `wiki/log.md`). Deferred to v0.3.

## Recommended Approach
B. Pulse on `vault.on('create'|'modify')` (ingest), a "Ask the brain" command highlighting the pages used, and a lint overlay for orphans and broken links from `resolvedLinks` and `unresolvedLinks`. Incremental layout so a change does not re-settle the whole brain.

## Open Questions
- Query highlighting: what is "ask" in v0.1? Proposal: a search box that lights up matching pages and their neighbors, with no LLM call at all (avoids API keys and network).
- Large vaults: cap at roughly 2k nodes with level-of-detail, or sample? Needs a benchmark in a real vault.
- Where to run the prototype: which vault is the test vault?

## Success Criteria
- Opens as a view from a ribbon icon and a command; renders the user's real vault; rotates smoothly (about 60 fps at 500 nodes on a laptop).
- A new note visibly pulses within 1 second.
- Lint overlay matches the broken-link count that Obsidian reports.
- Passes the automated review at community.obsidian.md with no errors.

## Distribution Plan
- Repo `jonyfs/llm-wiki-brain` with README.md, LICENSE (MIT), manifest.json, versions.json, esbuild config, `main.js` built by CI.
- GitHub Actions release workflow: tag `x.y.z` (must equal manifest `version`) builds and attaches `main.js`, `manifest.json`, `styles.css`.
- 0.1.0: BRAT beta. Then submit at community.obsidian.md (sign in, link GitHub, add plugin; the `id` must be unique and not contain `obsidian`). Later releases are fetched straight from GitHub.
